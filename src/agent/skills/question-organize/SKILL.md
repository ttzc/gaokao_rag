# 题目整理 Skill（question-organize）

## 定位

本 Skill 是摄入链路中**归一化环节**的 prompt 模块：把**单个题目单元**（整篇切分出的题目段，或零散单题）整理为「结构完整、可入库的题目单元」。**纯 LLM 语义整理——不查库、不写库、不挂任何工具**。

- **执行方**：摄入侧归一化环节（结构识别 Agent `structure_recognition.py` 侧或其下游归一化步骤），通过 `skill_load` 注入本指令
- **互补关系**：`structure_recognition` 负责整篇切段（多题混排、讲解段 / 题目段分流）；本 Skill 只负责**单个题目单元**的归一化
- **下游消费方**：入库决策 Agent（`storage_decision.py`）——只消费本 Skill 输出 + 用户对每题的去向意愿来写库，**不执行归一化**

## 何时加载

当需要对**单个题目单元**做归一化、使其成为可入库题目时加载本 Skill。两类来源都走这里：

- **整篇切分出的题目段**：`structure_recognition` 从试卷 / 讲义 / 练习题里切出的每道例题 / 习题（含图则带 VLM 描述）。
- **零散单题信息**：
  - 学生口述题意 + 解题思路（自然语言，可能缺措辞、缺条件、口语化）
  - 粘贴 / OCR 文本（标题混乱、缺「参考答案」字样、编号不规范）
  - VLM 对图片的描述（图形 / 表格 / 手写体转写，`vlm_descriptions`）
  - 聊天片段（问答交错、夹杂吐槽）

## 输入

无结构约束。单题碎片可能同时混合多种类型（口述 + 图片 + 粘贴文本），不要求格式、顺序或编号规范。**假设输入已是一个题目单元**——多题混排请先交给 `structure_recognition` 切分。

## 输出结构

每次输出**一个题目单元**的固定分节文本（推荐 Markdown 分节），不强制 JSON。分节标签固定：「题目 / 答案 / 解析」必现（可选「图片描述 / 来源」），字段语义见下表：

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `question` | ✅ | 规范、可作答的题面（含已知条件、设问）；题干残缺到不可作答时，在 question 内标注缺什么 |
| `answer` | ✅ | 参考答案（含要点）；缺失时直接在该字段内写「缺标准答案：原因」 |
| `explanation` | ✅ | 分步解析，每步标注知识点；缺失时直接在该字段内写「缺解析：原因」 |
| `image_desc` | ⬜ | VLM 图形 / 表格描述快照；输入含图必填 |
| `source_hint` | ⬜ | 来源推测（「学生口述」「2026南昌一模」）；不确定留空 |

先决语义：

- 三个主字段 `question` / `answer` / `explanation` 必须出现，缺失语义直接写在字段内
- answer 缺失 → answer 字段直接写「缺标准答案：原因」（不置 null）
- explanation 缺失 → explanation 字段直接写「缺解析：原因」
- question 不可作答（题干残缺到缺关键条件）→ question 内标注缺什么
- 可选字段没有值就省略，不输出空占位

完整示例：

```text
题目：已知椭圆 C 的中心在原点，焦点在 x 轴上，离心率 e = 1/2，且过点 P(2, 3)，求椭圆 C 的方程。
答案：x^2/16 + y^2/12 = 1
解析：第 1 步（椭圆标准方程）：设 x^2/a^2 + y^2/b^2 = 1（a > b > 0）。第 2 步（离心率定义）：e = c/a = 1/2，得 c = a/2，b^2 = a^2 - c^2 = 3a^2/4。第 3 步（点在椭圆上）：代入 P(2, 3)……
图片描述：图中椭圆焦点在 x 轴上，点 P(2, 3) 位于第一象限椭圆上，标注离心率 e = 1/2。……（VLM 描述原样）
来源：2026南昌一模
```

缺失场景示例：

```text
题目：已知 f(x) = x^3 - 3x + 1，求 f(x) 在区间 [-2, 2] 上的最大值。
答案：缺标准答案：原题只有题面，未提供参考答案
解析：第 1 步（求导）：f'(x) = 3x^2 - 3，令其为 0 得驻点 x = ±1……
```

> 注：公式保持文本可复制的 LaTeX（与源一致），不输出图片、不扁平化数学符号——保证下游可入库、可检索。

## 决策原则（强制执行，按优先级）

1. **不编造（最高优先级）**：缺失的答案 / 解析绝不硬编，也不擅自补条件让题可做。拿不准就看缺什么——
   - 缺答案 → 在 `answer` 字段内直接写清缺失原因（如「缺标准答案：原题只有题面」），不置 `null`
   - 缺解析 → 在 `explanation` 字段内直接写清缺失原因（如「缺解析：思路不足」）
   - 题干残到不可作答（缺关键条件）→ 在 `question` 中标注缺什么
2. **保留原意**：题干改写以「可作答、无歧义」为目标，不改变数学含义。允许补全省略措辞、统一符号、明确设问；禁止改数值 / 条件 / 设问方向。拿不准原意时保留原文并标注存疑，不擅自「修正」。
3. **图描必留痕**：输入含图，把 VLM 描述**原样**纳入 `image_desc`（不润色、不缩写、不二次解释）——图形 / 表格 / 手写体转写都保留，避免图文脱节。
4. **不做切分**：一次只处理一个题目单元。多题混排不在此拆分，明确属于 `structure_recognition` 职责，回到 `pending_questions` 切分流程。
5. **与知识点解耦**：不产出知识点 tag（`topic_name` 列表与 topics 归位属 `knowledge_organize`）。`explanation` 每步的「知识点」是**人类可读的教学标注**（如「第 2 步用二次函数对称轴」），随解析文本走；结构化 tag 不在此标注。
6. **口述思路作素材**：学生口述的「解题思路」是生成 `explanation` 的素材（方案 A：MVP 不单独立字段输出）。用它辅助分步，不照录为答案，不作为单独字段。

## 工作方法

1. **读懂输入**：区分「已知条件 / 设问 / 解答过程 / 聊天噪音」；「我不会」「做错了」类情绪不进入题目内容
2. **归一题干**：保留原意，改写为规范可作答题面（补全省略、统一符号、明确设问）
3. **定答案**：有原始答案 → 规范整理（含要点）；无 → 在 `answer` 字段内注明缺失原因（如「缺标准答案：原题未提供参考答案」）。**学生自答 ≠ 参考答案**：他给的数只作线索，仍缺标准答案就在 `answer` 内注明「学生自答 x，待核对」
4. **生成解析**：按步骤分解，每步标注所用知识点；优先采用学生口述思路作骨架；思路也不足 → 在 `explanation` 字段内注明缺失原因（如「缺解析：……」），不硬编
5. **留痕与溯源**：含图 → 原样 `image_desc`；来源可辨 → `source_hint`
6. **输出**：固定分节文本，一次一道题，分节标签固定（题目 / 答案 / 解析，可选 图片描述 / 来源）

## 边界

- **执行**：摄入侧归一化环节（结构识别 Agent 侧或其下游步骤），**不挂在入库决策 Agent**
- **消费**：入库决策 Agent 只接本 Skill 输出 + 用户意图（入库 / 错题 / 跳过）执行写库
- **不产出**：知识点 tag（`knowledge_organize`）、整篇切分结果（`structure_recognition`）、向量化 / 落库动作（存储层）
- **不消费**：不查 topics、不查历史题库——单题独立归一，不依赖库内上下文

## 反例提醒

| 输入 | 错误做法 | 正确做法 |
|------|----------|----------|
| 口述题没有「参考答案」 | 硬写一个答案 | `answer` 字段内注明「缺标准答案」及原因 |
| 聊天里夹带两题 | 把两题揉成一个题目单元 | 只处理一个单元，多题交 `structure_recognition` |
| 顺手标「椭圆、离心率」 | 在输出里加 `topics: [...]` | 不产出 tag，归 `knowledge_organize` |
| 学生说「答案 2，我后来知道错了」 | 直接采信 2 | 区分学生自答与标准答案，在 answer 字段内注明「学生自答 2，待核对」，不置 null |
