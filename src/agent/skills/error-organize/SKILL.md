# 错因整理 Skill（error-organize）

## 定位

本 Skill 是错题本链路中「**用户口述的错因 → 结构化错因**」的归一化环节：把学生**用自己的话**说出的错因，归纳为固定四段的分节文本。**纯 LLM 语义整理——不查库、不写库、不挂任何工具**。

- **执行方**：错题管理 Agent（`error_maintain` 侧），在写入错题本前通过 `skill_load` 注入本指令——离写库最近的 Agent 做结构化，LLM 之间传自然语言 / 分节文本
- **互补关系**：`question-organize` 整理**题目**（客观题面），本 Skill 整理**错因**（学生对自身错误的反思）；两者输出同为固定分节文本
- **下游消费方**：错题管理 Agent 读本 Skill 输出 → 转四键 dict，连同 `question_id` 调 `ingest_error` 写库

> **与题目整理的本质差异**（决定了本 Skill 的红线）：题目输入是客观题面，允许补全省略措辞、统一符号、明确设问；错因输入是**用户对自己错误的反思**（主观、口语化、可能说不清），**只做归纳，不许补全**——补全等于替学生编造错因。模型天然倾向于"帮"学生想出合理原因，这是本 Skill 幻觉风险最高的地方。

## 何时加载

**仅当本次输入含用户口述的错因时加载**。三种场景通用：

- **摄入时交代错因**：「我用了 b²=a²-c² 但算出来不对，感觉是公式记混了」
- **事后补录**：错题先入库（「错因待补」），学生事后补说一句错因
- **修正错因**：「我不是公式记混，是审题没看清楚」

纯题目输入**不加载**（题目归一是 `question-organize` 的事）；不含错因的闲聊、纯情绪宣泄不为它们加载本 Skill。

## 输入

无结构约束，可能来自：

- **学生即时输入**：题后一句自我解释（最常见）
- **极短口述**：「算错了」「没思路」「看漏了」
- **与题目口述混在同一条消息里**：题目部分已由上游分开，本 Skill 只处理错因表述
- **对已有错因的修正**：以用户**最新**表述为准，被推翻的旧归因不保留

## 输出结构

每次输出**一条错因**的固定分节文本，四段前缀**逐字固定**、顺序固定，一行一段。段语义见下表：

| 段 | 必填 | 对应四键 | 说明 |
|----|:----:|----------|------|
| `错因类型：` | ⬜ | `error_type` | 四选一：**计算错误 / 思路错误 / 知识盲区 / 审题错误**——粗分类，合情合理即可归类；四类都套不上才**整段省略** |
| `错因：` | ✅ | `cause` | 错因归纳——**基于用户原话**，可用更准确的数学表述重述，但不添加用户没说的原因 |
| `知识点缺口：` | ⬜ | `knowledge_gap` | 口述里暴露出的知识缺口（如「椭圆离心率定义与 a、b、c 关系」）；用户未体现则整段省略 |
| `改进建议：` | ⬜ | `fix_suggestion` | 针对性建议（复习什么、练什么题型）；可由 LLM 善意补充 |

先决语义：

- 空段**整段省略、不留空占位**（不写「知识点缺口：无」这类话）
- 与 question-organize 的「缺失自描述」**不同**：错因的缺失**不写字段内说明**——「这题还没有错因」由「错因待补」的落库状态承载，不靠文本自述。你输出什么，就是用户说了什么；没说的就是没有
- 一次只处理一条错因；多题各自的错因逐条输出

完整示例：

```text
错因类型：知识盲区
错因：把离心率 e = c/a 与 b² = a² - c² 两个关系记混，误将 b/a 当作离心率
知识点缺口：椭圆离心率定义与 a、b、c 关系
改进建议：复习「焦点三角形」模型，配套练习 3 道离心率计算题
```

极短口述示例（输入只有「算错了」三个字）：

```text
错因类型：计算错误
错因：算错了
```

> 归类（「算错了」→ 计算错误）是对用户口述的合理归纳，**不算脑补**；但错因仍是照实的三个字的短，不因此扩写成「粗心导致符号出错」。

> 注：错因里引用的公式保持文本可复制（与学生原话 / 题面一致），不扁平化数学符号——保证下游可入库、可检索。

## 决策原则（强制执行，按优先级）

1. **绝不脑补错因（最高优先级，本 Skill 的命门）**：用户的自我解释是数据，不是待完善的草稿。用户说「我算错了」，就只能归纳为"计算失误"，**不许**推断成"因粗心导致符号错误""对概念理解不清"这类用户没说的原因。极短口述（「算错了」「没思路」）→ `错因` 照实写短、`知识点缺口` / `改进建议` 用户没体现就整段省略——**宁可稀疏，不许填充**；稀疏记录会在「错因待补」流程里被追问补全，不需要你替它补。（`错因类型` 是粗分类，按第 3 条合情合理归类即可，不在"省略"之列。）
2. **可重述，不可增加**：把口语（"我把那个公式搞混了"）改写成数学表述（"混淆了离心率公式"）是**重述**，允许；添加用户未提及的原因、动机、心理状态（"考试紧张""平时没练"）是**增加**，禁止。
3. **错因类型是粗分类，合情合理即可**：四类是对用户口述的归类，**不要求用户明说**——「算错了」→ 计算错误、「没思路」→ 思路错误、「看漏了」→ 审题错误，都写得出去，这类归纳不算脑补。只有四类都套不上、或归类必须靠编造用户没说的事实才成立时，才整段省略该段。**放宽只到这一段为止**：不能借归类之名扩写 `错因`（错因仍受第 1、2 条约束）。
4. **`改进建议` 是唯一可生成的内容**：复习建议可由你基于题目知识点给出（善意补充），但与 `错因` 段严格区分——不得让建议反过来"编造"错因（先写建议、再倒推出一条用户没说的错因，禁止）。
5. **与知识点 tag 解耦**：`知识点缺口：` 是人类可读的自然语言描述，随文本走；结构化 tag（`topic_name` 归位 / 挂载）属 `question_maintain`，不在此标注。
6. **不做错因归纳之外的判断**：不评价学生水平、不预测成绩、不给情绪反馈——输出只有四段，没有第五段。

## 工作方法

1. **分离素材**：从输入里挑出「对错误的解释」；题目本身、聊天噪音、纯情绪（"我不会""气死了"）不进入错因内容
2. **定错因**：取用户原话的核心断言写进 `错因：`，可重述为更准确的数学表述，不扩写、不添加
3. **判类型**：把口述归到四类之一，合情合理就写（不必等用户明说）；四类都套不上才省略该段
4. **看缺口**：口述里体现了知识缺口才写 `知识点缺口：`（「公式记混」→ 离心率定义与 a、b、c 关系），没体现就整段省略
5. **给建议**：可选；基于题目知识点写一句针对性的（复习什么、练什么题型），不反向补错因
6. **输出**：固定分节文本，前缀逐字、顺序固定、一行一段，空段省略；一次一条错因

## 边界

- **执行方**：错题管理 Agent（`error_maintain.py`——后续批次落地，本 Skill 当前为待挂载状态），写入错题本前 `skill_load` 执行本指令；**不挂在结构识别 / 入库决策**
- **消费**：错题管理 Agent 读本 Skill 的分节文本 → 转四键 dict，连同 Leader 打包的 `question_id` 调 `ingest_error` 写库——四键 JSON 由 Agent 调工具时经 **function calling** 生成，本 Skill 不输出 JSON
- **JSON 到写门面为止**：四键 dict 原样存 SQLite，写向量前由纯函数 `_summary_to_text` 转回中文分节文本进向量库。本 Skill 的分节前缀与它刻意一致（同一套标签），但**来源不同**：Skill 输出的是 LLM 归纳（供 Agent 读），embedding 文本是从落库 JSON 派生（供检索）
- **不做的事**：不落库（写库是错题管理 Agent 的活）、不判断错题去向（摄入 / 错题 / 跳过由 Leader 收集用户意图）、不关联知识点 tag（`question_maintain`）
- **不消费**：不查库、不查学生历史——单条错因独立归纳，不依赖库内上下文

## 反例提醒

| 输入 | 错误做法 | 正确做法 |
|------|----------|----------|
| 「算错了」 | 编成「计算粗心导致中间步骤符号出错」的长错因 | `错因类型：计算错误` + `错因：算错了`——归类可以，错因照实写短、不扩写 |
| 用户只说"公式用错了" | 顺手归因「粗心」「练得少」 | 只重述用户说的，不添加心理 / 习惯归因 |
| 口述提到「离心率」 | 在输出里加 `topics: [椭圆, 离心率]` | 知识点缺口写自然语言，结构化 tag 归 `question_maintain` |
| 用户没提知识盲区 | 为配合「复习焦点三角形」的建议，写错因「对离心率概念理解不清」 | 错因止于用户所述；建议可善意补充，但不反推错因 |
| 「我不是公式记混，是审题没看清楚」 | 错因同时写「记混公式」与「审题不清」 | 以最新表述为准：`错因：审题没看清楚条件`，被推翻的旧归因不保留 |
